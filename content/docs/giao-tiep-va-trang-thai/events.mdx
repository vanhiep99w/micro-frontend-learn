Ở bài [contracts](/docs/giao-tiep-va-trang-thai/contracts), remote gọi một callback do shell truyền vào. Cách đó rõ ràng khi biết mình cần nhờ ai làm việc. Nhưng nếu **nhiều app cùng quan tâm đến một thay đổi**, có phải app phát phải gọi từng app nhận không?

Bài này đi theo **cách giao tiếp bằng event** trong [bản đồ tổng quan](/docs/giao-tiep-va-trang-thai#các-cách-giao-tiếp-và-bài-đọc-tiếp). App phát một thông báo có tên; các app cần nó đăng ký nghe qua một **event bus**, tức bộ phận chuyển thông báo.

<Callout type="info" title="Hai cách được kết hợp, không thay thế nhau">
  Ví dụ vẫn truyền bus qua tham số `mount`. `mount` cấp kết nối ban đầu; event là cách các app trao thông báo sau khi đã được gắn. Bus nhỏ chạy trong cùng document, không có backend và không tự lưu lịch sử.
</Callout>

## Khi nào dùng event thay vì callback

Giả sử Catalog vừa chọn sản phẩm 42. Recommendations — app gợi ý sản phẩm — cần đổi nội dung; một widget khác có thể muốn ghi nhận lựa chọn. Catalog không cần biết có bao nhiêu bên đang nghe; nó chỉ công bố “đã chọn sản phẩm 42”. Đó là **event**, thông báo việc đã xảy ra.

Ngược lại, nếu Catalog nhờ Cart thêm hàng và cần biết thành công hay thất bại, gọi API `addItem` rồi chờ kết quả thường dễ hiểu hơn. Đặt tên yêu cầu là event không giải quyết được việc ai xử lý và ai trả lỗi.

| Câu nói | Cơ chế nên bắt đầu |
| --- | --- |
| “Hãy thêm sản phẩm và cho tôi biết kết quả” | Hàm/API có input và kết quả |
| “Sản phẩm 42 vừa được chọn, ai cần thì cập nhật” | Event và các bên đăng ký nghe |

Sơ đồ chỉ mô tả đường chuyển thông báo trong browser, không phải message broker ở backend:

```d2 interactive=false title="App phát không gọi trực tiếp app nhận"
direction: down
catalog: Catalog
bus: "Bus chung"
recommendations: Recommendations
catalog -> bus: "Phát lựa chọn"
bus -> recommendations: "Gọi listener"
```

Shell tạo bus rồi cấp cùng object đó cho các app. Nếu mỗi app tự tạo một bus, chúng không nghe được nhau dù đặt cùng tên event.

## Tạo bus nhỏ để nhìn rõ đường đi

Bus dưới đây có hai thao tác: `publish` để phát, `subscribe` để đăng ký nghe. Hàm trả về từ `subscribe` dùng để **hủy đăng ký**, thường gọi là `unsubscribe`.

```js title="basic/bus.js" sourceFile="basic/bus.js" sourceRegion="main"
export function createBus() {
  const target = new EventTarget();

  return {
    publish(type, detail) {
      target.dispatchEvent(new CustomEvent(type, { detail }));
    },
    subscribe(type, handler) {
      const listener = (event) => handler(event.detail);
      target.addEventListener(type, listener);
      return () => target.removeEventListener(type, listener);
    },
  };
}
```

`EventTarget` giữ danh sách listener. `CustomEvent` mang theo dữ liệu ở `detail`. Ta bọc chúng thành API nhỏ để app nhận chỉ cần xử lý dữ liệu, không phải biết đối tượng event của browser.

Bus này gọi listener đồng bộ lúc publish, không chuyển việc sang background. Nó chưa validate dữ liệu, clone payload, cô lập lỗi handler hay xử lý Promise; chỉ dùng cho bài tập local với các handler nhỏ, đồng bộ và tin cậy. Bản mở rộng ở cuối bài bổ sung những phần đó.

## Phía phát và phía nhận viết gì

### Catalog phát thông báo sau khi chọn sản phẩm

Đây là code của app **Catalog**, không phải shell:

```js title="basic/catalog.js" sourceFile="basic/catalog.js" sourceRegion="main"
export function mount({ container, bus }) {
  const button = document.createElement('button');
  button.textContent = 'Chọn sản phẩm 42';

  function selectProduct() {
    bus.publish('catalog.product-selected.v1', {
      productId: '42',
    });
  }

  button.addEventListener('click', selectProduct);
  container.append(button);

  return {
    unmount() {
      button.removeEventListener('click', selectProduct);
      button.remove();
    },
  };
}
```

Người dùng bấm nút → `selectProduct` chạy → bus phát `catalog.product-selected.v1` với ID sản phẩm. Catalog không import Recommendations và không gọi hàm render của nó.

### Recommendations đăng ký nghe

Đây là app thứ hai. Nó nhận **cùng bus** từ shell:

```js title="basic/recommendations.js" sourceFile="basic/recommendations.js" sourceRegion="main"
export function mount({ container, bus }) {
  const label = document.createElement('p');
  label.textContent = 'Chưa nhận thông báo chọn sản phẩm';
  container.append(label);

  const unsubscribe = bus.subscribe(
    'catalog.product-selected.v1',
    ({ productId }) => {
      label.textContent = `Gợi ý cho sản phẩm ${productId}`;
    },
  );

  return {
    unmount() {
      unsubscribe();
      label.remove();
    },
  };
}
```

Tên `catalog.product-selected.v1` phải khớp hai phía. Khi nhận dữ liệu, app tự đổi giao diện của mình. Khi unmount, nó hủy listener trước khi xóa UI; nếu không, app đã rời trang vẫn có thể tiếp tục phản ứng.

Event vẫn là contract: hai team phải thống nhất tên, dữ liệu và ý nghĩa. Bus bỏ được import trực tiếp giữa hai app, không bỏ được nhu cầu thỏa thuận.

### Shell tạo đúng một bus rồi nối hai app

```js title="basic/shell.js" sourceFile="basic/shell.js" sourceRegion="main"
import { createBus } from './bus.js';
import { mount as mountCatalog } from './catalog.js';
import { mount as mountRecommendations } from './recommendations.js';

const bus = createBus();
const catalog = mountCatalog({
  container: document.querySelector('#catalog'), bus,
});
const recommendations = mountRecommendations({
  container: document.querySelector('#recommendations'), bus,
});

document.querySelector('#remove').addEventListener('click', () => {
  recommendations.unmount();
});
```

Đọc theo thứ tự: tạo bus → mount Catalog với bus → mount Recommendations với **chính bus đó** → người dùng chọn sản phẩm. Lúc bấm nút, shell không cần chuyển tiếp từng thông báo; bus đã giữ listener của Recommendations.

## Event không giữ trạng thái hiện tại thay cho bạn

Nếu Recommendations mount **sau** lần chọn sản phẩm, nó vẫn hiện “Chưa nhận thông báo”. Không có lỗi chuyển thông báo: lúc publish chưa có listener và bus không lưu lịch sử.

Đây là giới hạn quan trọng khi các micro-frontend tải vào những lúc khác nhau. Nếu app cần biết lựa chọn hiện tại ngay khi mở, owner phải cung cấp thêm cách đọc dữ liệu hiện tại — **snapshot** — rồi subscribe để theo dõi tiếp. Bài [State ownership](/docs/giao-tiep-va-trang-thai/state-ownership) triển khai đúng phần đó.

## Từ bài tập nhỏ tới bus dùng thật

| Việc cần bổ sung | Vì sao cần cho micro-frontend? |
| --- | --- |
| Validation và version event | App cũ/mới có thể cùng chạy; TypeScript lúc build không kiểm tra dữ liệu nhận lúc chạy |
| Cô lập và report lỗi listener | UI nhận lỗi không được biến thay đổi đã thành công thành thất bại |
| Payload chỉ có dữ liệu công khai | Không truyền store, React element hay token; `CustomEvent.detail` không tự clone object |
| Snapshot cho nơi đến muộn | App mở sau phải có cách đọc hiện tại, không đoán từ event đã mất |
| Quy tắc event lặp và dữ liệu cũ | Khi có revision đáng tin cậy, gán snapshot mới thay vì tự cộng từ số lần nhận event |
| Cleanup theo app và session | Unmount không để listener cũ sống; đổi user không giữ projection cũ |

Nếu phát thông báo “giỏ đã cập nhật”, hãy phát sau khi API xác nhận thay đổi. Một listener bị lỗi không có nghĩa server chưa thêm hàng. Event bus frontend không phải durable queue và không có đảm bảo exactly-once chỉ nhờ một ID.

## Mẫu TypeScript nâng cao để tra cứu

Các file dưới là **bộ mẫu khác, đầy đủ hơn cho giỏ hàng**, không phải những dòng cần chèn vào bài tập chọn sản phẩm. Bắt đầu từ `contracts/cart-events.ts` để xem dữ liệu, rồi `platform/cart-event-bus.ts` để xem validation và cách xử lý lỗi. `shell/bootstrap.ts` tạo bus; `cart/add-item.ts` phát sau xác nhận; `shell/CartBadge.tsx` nhận và đọc snapshot.

`eventId` nhận diện thông báo; `correlationId` nối nó với thao tác gốc; `revision` sắp thứ tự dữ liệu trong cùng giỏ theo cam kết backend. `occurredAt` phục vụ debug, không thay revision. Giới hạn ID/thời gian là lựa chọn mẫu, không phải chuẩn bắt buộc cho mọi app.

```ts title="contracts/cart-events.ts" sourceFile="contracts/cart-events.ts" sourceRegion="main"
export const CART_UPDATED = 'shop.cart.updated.v1' as const;

export type CartSnapshot = Readonly<{
  cartId: string;
  revision: number;
  itemCount: number;
}>;

export type CartUpdated = Readonly<{
  type: typeof CART_UPDATED;
  eventId: string;
  source: 'cart';
  occurredAt: string;
  correlationId: string;
  payload: CartSnapshot;
}>;

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null;
}

function isId(value: unknown): value is string {
  return typeof value === 'string'
    && value.trim().length > 0
    && value.length <= 200;
}

function isCount(value: unknown): value is number {
  return typeof value === 'number'
    && Number.isSafeInteger(value)
    && value >= 0;
}

export function isCartUpdated(value: unknown): value is CartUpdated {
  if (!isRecord(value) || !isRecord(value.payload)) return false;

  const payload = value.payload;
  return value.type === CART_UPDATED
    && value.source === 'cart'
    && isId(value.eventId)
    && isId(value.correlationId)
    && typeof value.occurredAt === 'string'
    && Number.isFinite(Date.parse(value.occurredAt))
    && isId(payload.cartId)
    && isCount(payload.revision)
    && isCount(payload.itemCount);
}
```

```ts title="platform/cart-event-bus.ts" sourceFile="platform/cart-event-bus.ts" sourceRegion="main"
import {
  CART_UPDATED,
  isCartUpdated,
  type CartUpdated,
} from '../contracts/cart-events';

type Handler = (event: CartUpdated) => void | Promise<void>;
type BusIssue = Readonly<{
  kind: 'invalid-event' | 'handler-error';
  eventType: typeof CART_UPDATED;
  eventId?: string;
}>;

export interface CartEventBus {
  publish(event: CartUpdated): void;
  subscribe(handler: Handler): () => void;
}

export function createCartEventBus(
  onIssue: (issue: BusIssue) => void,
): CartEventBus {
  const target = new EventTarget();

  function report(issue: BusIssue): void {
    try {
      onIssue(issue);
    } catch {
      // Telemetry hỏng không được làm hỏng đường xử lý UI.
      console.error('Event bus telemetry failed');
    }
  }

  return {
    publish(event) {
      if (!isCartUpdated(event)) {
        report({ kind: 'invalid-event', eventType: CART_UPDATED });
        throw new TypeError('Invalid cart.updated event');
      }

      // Copy các field được công bố, không chuyển object nội bộ.
      const detail: CartUpdated = Object.freeze({
        type: CART_UPDATED,
        eventId: event.eventId,
        source: 'cart',
        occurredAt: event.occurredAt,
        correlationId: event.correlationId,
        payload: Object.freeze({
          cartId: event.payload.cartId,
          revision: event.payload.revision,
          itemCount: event.payload.itemCount,
        }),
      });

      target.dispatchEvent(new CustomEvent(CART_UPDATED, { detail }));
    },

    subscribe(handler) {
      const listener: EventListener = (rawEvent) => {
        const detail: unknown = (rawEvent as CustomEvent<unknown>).detail;
        if (!isCartUpdated(detail)) {
          report({ kind: 'invalid-event', eventType: CART_UPDATED });
          return;
        }

        const failed = () => report({
          kind: 'handler-error',
          eventType: CART_UPDATED,
          eventId: detail.eventId,
        });

        try {
          // Bắt cả throw đồng bộ và rejection từ async handler.
          void Promise.resolve(handler(detail)).catch(failed);
        } catch {
          failed();
        }
      };

      target.addEventListener(CART_UPDATED, listener);
      return () => target.removeEventListener(CART_UPDATED, listener);
    },
  };
}
```

```ts title="cart/add-item.ts" sourceFile="cart/add-item.ts" sourceRegion="main"
import { CART_UPDATED, type CartSnapshot } from '../contracts/cart-events';
import type { CartEventBus } from '../platform/cart-event-bus';

type AddItemInput = {
  cartId: string;
  productId: string;
  quantity: number;
};

interface CartApi {
  addItem(
    input: AddItemInput,
    options: { idempotencyKey: string },
  ): Promise<CartSnapshot>;
}

export async function addItem(
  api: CartApi,
  bus: CartEventBus,
  input: AddItemInput,
  operationId: string,
): Promise<CartSnapshot> {
  const snapshot = await api.addItem(input, {
    idempotencyKey: operationId,
  });

  try {
    bus.publish({
      type: CART_UPDATED,
      eventId: crypto.randomUUID(),
      source: 'cart',
      occurredAt: new Date().toISOString(),
      correlationId: operationId,
      payload: snapshot,
    });
  } catch {
    // API đã commit: không báo mutation thất bại chỉ vì notification lỗi.
    // Production cần report metadata lỗi qua telemetry của cart domain.
    console.error('Cart committed, but notification failed', { operationId });
  }

  return snapshot;
}
```

```tsx title="shell/CartBadge.tsx" sourceFile="shell/CartBadge.tsx" sourceRegion="main"
import { useEffect, useState } from 'react';
import type { CartSnapshot } from '../contracts/cart-events';
import type { CartEventBus } from '../platform/cart-event-bus';

interface CartReader {
  // Implementation phải validate snapshot từ API trước khi return.
  getSnapshot(
    cartId: string,
    options: { signal: AbortSignal },
  ): Promise<CartSnapshot>;
}

type BadgeView = {
  cartId: string;
  itemCount: number | null;
  error: string | null;
};

export function CartBadge({ bus, reader, cartId }: {
  bus: CartEventBus;
  reader: CartReader;
  cartId: string;
}) {
  const [view, setView] = useState<BadgeView>({
    cartId,
    itemCount: null,
    error: null,
  });

  useEffect(() => {
    let active = true;
    let lastRevision = -1;
    const controller = new AbortController();
    setView({ cartId, itemCount: null, error: null });

    function apply(snapshot: CartSnapshot): void {
      if (!active || snapshot.cartId !== cartId) return;
      if (snapshot.revision <= lastRevision) return;
      lastRevision = snapshot.revision;
      setView({ cartId, itemCount: snapshot.itemCount, error: null });
    }

    const unsubscribe = bus.subscribe((event) => apply(event.payload));

    void reader.getSnapshot(cartId, { signal: controller.signal })
      .then(apply)
      .catch(() => {
        if (active && !controller.signal.aborted && lastRevision === -1) {
          setView({ cartId, itemCount: null, error: 'Không tải được giỏ hàng' });
        }
      });

    return () => {
      active = false;
      unsubscribe();
      controller.abort();
    };
  }, [bus, reader, cartId]);

  // Không hiển thị số lượng của cart cũ trong render đổi cartId.
  const current = view.cartId === cartId ? view : null;
  if (current?.error) return <span role="status">{current.error}</span>;

  return (
    <span aria-live="polite" aria-atomic="true">
      Giỏ hàng: {current?.itemCount ?? '…'}
    </span>
  );
}
```

```ts title="platform/recent-event-ids.ts" sourceFile="platform/recent-event-ids.ts" sourceRegion="main"
export function createRecentEventIds(ttlMs = 60_000, maxEntries = 1_000) {
  const seen = new Map<string, number>();

  return {
    has(eventId: string): boolean {
      const now = Date.now();
      for (const [id, expiresAt] of seen) {
        if (expiresAt <= now) seen.delete(id);
      }
      return seen.has(eventId);
    },

    remember(eventId: string): void {
      // Đưa ID đã cập nhật về cuối để eviction bỏ entry cũ nhất.
      seen.delete(eventId);
      seen.set(eventId, Date.now() + ttlMs);
      while (seen.size > maxEntries) {
        const oldest = seen.keys().next().value;
        if (oldest === undefined) break;
        seen.delete(oldest);
      }
    },

    clear(): void {
      seen.clear();
    },
  };
}
```

Trong React, subscribe nằm trong effect và return cleanup, không subscribe ngay trong render. Badge mẫu đăng ký trước khi fetch rồi bỏ snapshot có revision cũ; `active` và abort chặn cập nhật sau unmount. Điều này không tự phát hiện thay đổi ở thiết bị khác: vẫn cần refetch khi trở lại trang hoặc server push theo chính sách.

Cache `recent-event-ids` có giới hạn và thời hạn, không bảo đảm side effect chỉ xảy ra một lần. File `fragments/cart-event-bus.spec.ts` là ý tưởng assertion, cần import và test runner phù hợp, không phải test suite chạy độc lập.

## Các lỗi nên kiểm tra trước

| Hiện tượng | Kiểm tra |
| --- | --- |
| Phát mà không ai nhận | Cùng instance bus, đúng tên event, listener đã mount chưa? |
| Một lần phát chạy nhiều lần | Cleanup, nhiều publisher hoặc bridge lặp? |
| Mở app thấy số cũ/trống | Có đọc snapshot ban đầu không? |
| Dữ liệu mới bị ghi đè | Response cũ có bị loại bằng scope/revision đúng contract không? |
| Đổi tài khoản vẫn thấy dữ liệu cũ | Listener, request và snapshot của phiên cũ đã bị vô hiệu hóa chưa? |

Với iframe, dùng `postMessage` và kiểm tra origin/source, không truyền bus chứa function trực tiếp. Với nhiều tab có thể dùng `BroadcastChannel`; đóng channel khi kết thúc và tránh relay vòng. Những môi trường đó không chia sẻ tự động một bus trong bộ nhớ.
