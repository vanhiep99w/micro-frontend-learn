Catalog có nút mở sản phẩm, shell có nút mở giỏ hàng. Nếu hai app tự ghi thanh địa chỉ mà không phối hợp, URL có thể đã là `/cart` nhưng màn hình vẫn đang ở Catalog.

Bài này đi theo nhánh **URL và API điều hướng** trong [bản đồ giao tiếp](/docs/giao-tiep-va-trang-thai#các-cách-giao-tiếp-và-bài-đọc-tiếp). Shell giữ một đường điều phối URL; remote nhận location hiện tại và gửi yêu cầu navigation qua API đã được truyền khi mount.

<Callout type="info" title="Chọn đúng mô hình trước khi copy code">
  Ví dụ JavaScript đầu dành cho app mount riêng hoặc khác framework, chưa dùng thư viện router. Nếu các remote render như component trong cùng cây React, một React Router chung thường đơn giản hơn; mẫu đó ở phần sau. Không cần tạo bridge riêng chỉ vì có nhiều remote.
</Callout>

## Shell chọn app còn remote chọn màn hình

| URL | Shell quyết định | Remote quyết định |
| --- | --- | --- |
| `/catalog` | Gắn Catalog | Màn hình danh sách |
| `/catalog/products/42` | Vẫn Catalog | Chi tiết sản phẩm 42 |
| `/catalog/search` | Vẫn Catalog | Màn hình tìm kiếm |
| `/cart` | Gắn Cart | Nội dung giỏ hàng |

Shell nhận cả nhánh `/catalog` và `/catalog/*`, không liệt kê mọi trang con. Catalog thêm trang dưới prefix được giao thì không bắt shell deploy theo. Đổi prefix công khai lại là thay đổi contract cần phối hợp và giữ link cũ.

**Route** là quy tắc URL → nội dung. **Navigation** là hành động chuyển URL. Remote cần cả hai: biết URL để chọn màn hình, có cách yêu cầu chuyển tới URL mới.

```d2 interactive=false title="Hai cấp trách nhiệm không nhất thiết là hai router"
direction: down
url: "/catalog/products/42"
shell: "Shell chọn Catalog"
remote: "Catalog chọn sản phẩm 42"
url -> shell -> remote
```

Một URL có thể ghép nhiều remote theo layout. Widget gợi ý chỉ cần nhận product ID, không bắt buộc có router. Đừng biến “mỗi micro-frontend” thành “mỗi micro-frontend phải tự điều khiển browser history”.

## Shell tạo navigation API

Mẫu nhỏ dùng History API của browser, chỉ cho phép `/catalog...` hoặc `/cart` trong cùng origin:

```js title="basic/navigation.js" sourceFile="basic/navigation.js" sourceRegion="main"
export function createNavigation() {
  const listeners = new Set();
  const read = () => Object.freeze({
    pathname: location.pathname,
    search: location.search,
    hash: location.hash,
  });
  let snapshot = read();

  function notify() {
    snapshot = read();
    for (const listener of [...listeners]) listener();
  }
  window.addEventListener('popstate', notify);

  return {
    getSnapshot: () => snapshot,
    subscribe(listener) {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
    navigate(path, { replace = false } = {}) {
      const url = new URL(path, location.origin);
      if (url.origin !== location.origin || url.username || url.password
        || !/^\/(catalog(?:\/.*)?|cart)$/.test(url.pathname)) {
        throw new Error('Đích đến không được hỗ trợ');
      }
      const next = url.pathname + url.search + url.hash;
      if (replace) history.replaceState(null, '', next);
      else history.pushState(null, '', next);
      notify();
    },
    dispose() {
      window.removeEventListener('popstate', notify);
      listeners.clear();
    },
  };
}
```

Có ba đường quan trọng:

- `navigate` thay URL qua `pushState`/`replaceState` rồi **tự gọi `notify`**.
- Browser Back/Forward phát `popstate`, `notify` đọc lại URL.
- `getSnapshot/subscribe` cho mọi UI cùng biết location hiện tại.

`pushState` và `replaceState` không tự phát `popstate`. Đây là lý do chỉ đổi URL ở remote chưa bảo đảm router/UI của shell biết thay đổi. Mẫu không liên tục polling thanh địa chỉ; nó phát notification đúng nơi URL đổi.

## Remote dùng API để mở trang và nhận location

```js title="basic/catalog.js" sourceFile="basic/catalog.js" sourceRegion="main"
export function mount({ container, navigation }) {
  const section = document.createElement('section');
  const title = document.createElement('h2');
  const product = document.createElement('button');
  product.textContent = 'Xem sản phẩm 42';
  section.append(title, product);
  container.append(section);
  let active = true;

  function render() {
    if (!active) return;
    const { pathname, search } = navigation.getSnapshot();
    const page = pathname.slice('/catalog'.length) || '/';
    title.textContent = `Catalog: ${page}${search}`;
  }
  function openProduct() {
    navigation.navigate('/catalog/products/42');
  }

  const unsubscribe = navigation.subscribe(render);
  render();
  product.addEventListener('click', openProduct);
  return {
    unmount() {
      active = false;
      unsubscribe();
      product.removeEventListener('click', openProduct);
      section.remove();
    },
  };
}
```

Khi người dùng bấm nút, Catalog gọi `navigation.navigate(...)`. Khi snapshot đổi, `render` chỉ chọn nội dung từ URL. **Không gọi lại `navigate` từ `render`**, nếu không Back có thể vừa quay về rồi lại bị push tới trang vừa rời.

`slice('/catalog'.length)` ở đây chỉ minh họa phần đường dẫn Catalog được giao. App thật dùng router/matcher để chọn màn hình, validate/encode tham số, hiển thị not found nếu route hoặc resource không tồn tại.

## Shell gắn và tháo app theo URL

```js title="basic/shell.js" sourceFile="basic/shell.js" sourceRegion="main"
import { createNavigation } from './navigation.js';
import { mount } from './catalog.js';

const navigation = createNavigation();
const outlet = document.querySelector('#outlet');
let catalog;

function render() {
  const { pathname } = navigation.getSnapshot();
  if (pathname === '/catalog' || pathname.startsWith('/catalog/')) {
    if (!catalog) {
      outlet.replaceChildren();
      catalog = mount({ container: outlet, navigation });
    }
  } else {
    catalog?.unmount();
    catalog = undefined;
    outlet.textContent = pathname === '/cart' ? 'Cart UI' : 'Trang chủ';
  }
}
navigation.subscribe(render);
render();
document.querySelector('#catalog').addEventListener('click', () => {
  navigation.navigate('/catalog');
});
document.querySelector('#cart').addEventListener('click', () => {
  navigation.navigate('/cart');
});
```

Lần mở `/catalog`, shell gắn Catalog. Khi chuyển sang sản phẩm, shell giữ instance Catalog vì prefix vẫn thuộc nó; listener Catalog cập nhật màn hình bên trong. Khi đi `/cart`, shell tháo Catalog và hiện Cart giả lập.

Shell không import từng màn hình của Catalog. Phần tải remote được bỏ qua ở bài tập, giống ví dụ mount trong bài [contracts](/docs/giao-tiep-va-trang-thai/contracts).


Mở `http://localhost:8080`. Bấm **Mở Catalog** → **Xem sản phẩm 42** → **Mở Cart**, rồi dùng Back/Forward của browser. URL và nội dung phải cùng thay đổi. Ví dụ chỉ dùng button để ngắn gọn; production dùng link có `href` thật, xử lý click thường qua router/API và giữ mở tab mới, bàn phím, focus, title/scroll đúng hành vi.

Các module đặt cạnh nhau để tập trung vào luồng giao tiếp. Import tương đối không minh họa tải remote, Module Federation hay pipeline deploy độc lập. Khi tách bundle, loader phải cung cấp đúng API đã thống nhất; thứ tự truyền và gọi hàm vẫn như trong ví dụ.


Server HTTP đơn giản trên không có SPA fallback. **Không dùng kết quả click để kết luận refresh URL sâu đã hoạt động**; phần server routing được giải thích bên dưới.

## Vì sao URL đổi mà router chưa cập nhật

Hai `BrowserRouter` độc lập trong cùng document cùng nhìn một browser history thật, nhưng có location/subscription riêng. Catalog tự `pushState` không báo cho router shell qua `popstate`.

```d2 title="Sau khi Catalog điều hướng: browser đã đổi, shell chưa nhận thông báo"
direction: down
navigation: Catalog điều hướng tới /cart
browser: Browser {
  address: "URL trên thanh địa chỉ = /cart"
  history: "History entry hiện tại = /cart"
}
catalog: "Location trong router Catalog = /cart"
shell: "Location trong router shell = /catalog\nChưa được cập nhật" {
  style.stroke: "#b45309"
}
navigation -> browser: pushState thành công
navigation -> catalog: Router Catalog cập nhật
browser -> shell: "Không tự phát popstate\nShell chưa được thông báo" {style.stroke-dash: 4}
```

Browser URL không sai; **state location trong router shell chưa cập nhật**. Nếu đọc trực tiếp `window.location.pathname`, shell vẫn thấy URL mới, nhưng router cần notification để render lại. Back/Forward có phát `popstate`; điều đó không làm các lệnh push riêng lẻ tự được đồng bộ.

Chọn một router chung hoặc một cơ chế bridge có hai chiều: remote yêu cầu đi, shell công bố location. Không mặc định chạy hai browser router rồi hy vọng chúng tự nối.

## Khi các app cùng cây React thì dùng router chung

Nếu shell render `CatalogRoutes` như component dưới router của mình, không cần navigation adapter JavaScript ở trên. `Link`/`useNavigate` của remote đi qua cùng router context.

### Shell giao nhánh route cho Catalog

```tsx title="shell/App.tsx" sourceFile="shell/App.tsx" sourceRegion="main"
import { BrowserRouter, Link, Route, Routes } from 'react-router';
import { CatalogRoutes } from 'catalog/routes';
import { CartPage } from 'cart/Page';

export function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/catalog">Sản phẩm</Link>
        {' | '}
        <Link to="/cart">Giỏ hàng</Link>
      </nav>

      <Routes>
        <Route path="/" element={<p>Trang chủ</p>} />
        <Route path="/catalog/*" element={<CatalogRoutes />} />
        <Route path="/cart" element={<CartPage />} />
        <Route path="*" element={<p>Không tìm thấy trang</p>} />
      </Routes>
    </BrowserRouter>
  );
}
```

`/catalog/*` nhận cả nhóm URL. `BrowserRouter` chỉ được tạo ở shell. Các module remote `catalog/routes`, `cart/Page` là tên giả định cần loader/remote config, không phải dependency của site docs.

### Catalog khai báo route con chứ không tạo BrowserRouter mới

```tsx title="catalog/routes.tsx" sourceFile="catalog/routes.tsx" sourceRegion="main"
import { Link, Route, Routes, useParams } from 'react-router';

function ProductList() {
  return (
    <section>
      <h2>Danh sách sản phẩm</h2>
      <Link to="/catalog/products/42">Xem sản phẩm 42</Link>
    </section>
  );
}

function ProductDetail() {
  const { productId } = useParams();
  return <h2>Chi tiết sản phẩm {productId}</h2>;
}

export function CatalogRoutes() {
  return (
    <Routes>
      <Route index element={<ProductList />} />
      <Route path="products/:productId" element={<ProductDetail />} />
      <Route path="search" element={<p>Tìm kiếm sản phẩm</p>} />
      <Route path="*" element={<p>Không có trang này trong Catalog</p>} />
    </Routes>
  );
}
```

`Routes` chọn các màn hình, không tạo browser history mới. `index` nhận `/catalog`, `products/:productId` nhận phần sau prefix. Khi chuyển sản phẩm → Cart → Back, router chung chọn app và route con tương ứng.

Hai `createRoot` riêng không tự nhận cùng React Context dù cùng cài router. Nếu cần root riêng hoặc framework khác, dùng navigation API/adapter. Với data router, ghép route objects/loaders theo API phù hợp, không coi descendant `Routes` ở mẫu này là cấu hình đầy đủ mọi loader/action.

## Navigation contract cho remote cô lập

Contract TypeScript dưới mô tả bản mở rộng: remote đọc location, dựng link thật và yêu cầu chuyển tới destination có cấu trúc. Nó là API mẫu, **chưa có implementation**; khác với basic/navigation.js đã viết ở trên.

<details>
<summary>Xem contracts/navigation.ts</summary>

```ts title="contracts/navigation.ts" sourceFile="contracts/navigation.ts" sourceRegion="main"
export type LocationSnapshot = Readonly<{
  revision: number;
  pathname: string;
  search: string;
  hash: string;
}>;

export type Destination =
  | Readonly<{ name: 'catalog.list' }>
  | Readonly<{ name: 'catalog.product'; productId: string }>
  | Readonly<{ name: 'cart' }>;

export interface NavigationPort {
  getSnapshot(): LocationSnapshot;
  subscribe(listener: () => void): () => void;
  href(destination: Destination): string;
  navigate(
    destination: Destination,
    options?: Readonly<{ replace?: boolean }>,
  ): Promise<'committed' | 'cancelled'>;
}
```

</details>

<SourceRef project="giao-tiep-va-trang-thai-routing" file="contracts/navigation.ts" region="main">Đối chiếu navigation port đầy đủ</SourceRef>

`href` dựng link, không chuyển trang. `navigate` mặc định push; `committed` chỉ nghĩa là location đã được chấp nhận, không chứng minh remote/dữ liệu tải xong. Guard từ chối hoặc yêu cầu bị thay thế có thể trả `cancelled`; destination sai hoặc adapter lỗi thì reject.

Snapshot bất biến và reference ổn định khi chưa đổi. `search/hash` gồm dấu `?/#` khi có; mẫu quy ước pathname chưa có application basename. Adapter phải chuyển đổi nhất quán, tránh thêm prefix hai lần.

Remote dùng memory router vẫn phải nhận snapshot ban đầu và mọi lần URL đổi. `initialEntries` chỉ khởi tạo memory history, không phải cơ chế đồng bộ liên tục. Khi áp dụng location từ shell, cập nhật router bên trong theo adapter phù hợp mà không gửi ngược thêm một yêu cầu push. Iframe cần message protocol và origin/source validation, không truyền port chứa function trực tiếp.

## Push replace URL filter và server routing

### Back và Forward đi theo history thật

```d2 title="Push tạo entry; Back quay về entry trước"
direction: right
catalog: /catalog
product: /catalog/products/42
cart: /cart
catalog -> product: Push mở sản phẩm
product -> cart: Push mở giỏ hàng
cart -> product: Back lần 1
product -> catalog: Back lần 2
```

Push thêm entry để Back quay lại. Replace thay entry hiện tại, phù hợp chuẩn hóa URL hoặc bỏ màn hình callback đã xử lý. Khi nhận Back/Forward, chỉ áp dụng location, không push lại.

“Về danh sách” cũng không nhất thiết là Back: người dùng mở link sản phẩm từ email có thể chưa từng qua danh sách. Không giữ dữ liệu cần dựng màn hình chỉ trong `history.state`, vì mở link ở tab mới không có object entry cũ.

### Filter cần chia sẻ thì đưa vào URL

`/catalog?sort=price-asc&page=2` có thể dựng lại sau reload hoặc gửi link. Catalog đọc/validate query theo contract; input đang gõ chưa submit vẫn có thể là local state. Tránh push từng ký tự; replace phù hợp cho cập nhật draft liên tục nếu cần URL.

Khi sửa query của mình, giữ query khác theo quy ước, không tự ghi đè mọi tham số. Không lưu token, mật khẩu hay dữ liệu riêng tư vào URL. Application basename như `/shop`, điểm gắn remote `/catalog` và URL CDN tải asset là ba thứ khác nhau.

### Refresh URL sâu còn cần server

Click trong SPA có frontend xử lý. Refresh `/catalog/products/42` gửi request document tới server trước khi JavaScript chạy. Với static SPA, server cần trả HTML shell cho route màn hình phù hợp và giữ URL, không redirect mất điểm đến.

Không rewrite chunk/API lỗi thành shell HTML. Asset JavaScript thiếu phải trả lỗi asset, không trả HTML 200. Với Next.js/SSR dùng pipeline routing của framework, không sao chép SPA fallback máy móc.

## Kiểm tra lúc ghép các app

| Thử | Điều cần thấy |
| --- | --- |
| Catalog thêm trang dưới prefix được giao | Không cần shell liệt kê route con mới |
| Sản phẩm → Cart → Back → Forward | URL và UI khớp, không tạo vòng push |
| Refresh/link sâu trên hosting thật | Server và frontend cùng hiểu URL |
| Remote tải chậm rồi người dùng sang app khác | Kết quả cũ không mount đè app mới |
| Vùng cần login | Chờ bootstrap session; không coi đang kiểm tra là anonymous |
| App không có route | Chỉ nhận props/callback, không bắt buộc tạo router |

Route guard chỉ điều khiển trải nghiệm, backend vẫn kiểm tra quyền. `returnTo` sau login phải được parse/allowlist, không tin chuỗi chỉ vì bắt đầu bằng `/`. Dọn subscription khi remote unmount và kiểm tra navigation generation sau các bước tải bất đồng bộ.
