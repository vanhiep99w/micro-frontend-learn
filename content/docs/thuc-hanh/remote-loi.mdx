## Kết quả cần đạt

| Fault | Bằng chứng cần có |
| --- | --- |
| Catalog entry bị chặn | Catalog fallback; shell và cart vẫn hoạt động |
| Entry đến sau deadline | Fallback không tự biến thành catalog; không có lần mount muộn |
| Promise import reject sau deadline | Không có unhandled rejection; không phát thêm failure cho cùng slot |
| Lazy module trả 404 | Catalog vẫn usable, chỉ phần chi tiết báo lỗi; cart giữ số lượng |
| Contract major không khớp | Không gọi mount; không retry cùng release tự động |
| Evaluation hoặc mount throw | Slot lỗi được cô lập; telemetry phân biệt phase |
| Cart entry không tải | Không hiển thị cart rỗng giả; thêm hàng không được báo thành công |
| Rollback r19 về r18 | Document mới chọn r18; tab cũ vẫn pin r19 |
| Shared React requirement sai | Có lỗi compatibility thật của webpack, không chỉ warning hay lỗi network |

Mình không bật auto-retry trong lab. Browser có thể dùng `TypeError` cho nhiều lỗi import khác nhau, nên chỉ nhìn tên exception không đủ kết luận “network transient”. Với lỗi contract, evaluation hoặc shared version, thử lại cùng release thường không giúp gì. Với timeout, operation cũ còn có thể đang chạy.

Các deadline `2000 ms` và delay `2600 ms` bên dưới chỉ là số minh họa để phân biệt hai nhánh test, không phải khuyến nghị cho production.

## Phân biệt các failure boundary

```d2 title="Phân biệt các failure boundary"
direction: right
shell: Shell
config: "Config snapshot\nLỗi bắt buộc → dừng bootstrap"
catalog: "Catalog entry → validate → mount\nLỗi entry/mount → fallback slot\ncatalog"
details: "Lazy details\nLỗi → catalog báo lỗi phần chi\ntiết"
cart: "Cart entry → validate → mount\nGiữ slot cart khi catalog lỗi"
command: "Add command\nLỗi → báo thao tác, không tải\nlại code"
shell -> config
config -> catalog -> details
config -> cart -> command
```

Entry trả 200 chưa chứng minh remote hoạt động: nó có thể import một chunk thiếu, throw lúc evaluation hoặc expose sai API. Ngược lại, một API/command thất bại không có nghĩa code remote cần tải lại.

Lab ESM dùng `try/catch` quanh import, validation và **mount đồng bộ**. Đây không phải React Error Boundary. Trong shop React, boundary chỉ bắt lỗi render/lifecycle trong cùng React tree và lỗi mà `lazy()` đưa vào render; event handler và Promise tùy ý vẫn cần xử lý riêng. Remote có React root riêng cần boundary riêng bên trong root đó.

- Server phục vụ `/runtime/*.json` với `no-store`, artifacts theo release path với cache dài.

Nếu r19 chưa tồn tại, chạy **một lần**:

```bash

```

Không chạy lại lệnh này trên thư mục r19 đã publish: build script phải từ chối overwrite. Với workspace đã dùng trong bài trước, giữ artifact hiện có và chọn revision config mới.

```bash
node candidate.mjs r18 cfg-101
```

## Bước 1 tạo slot có deadline

### State machine và policy phục hồi

```d2 title="State machine và policy phục hồi"
direction: down
idle: Idle
loading: Loading
ready: Ready
failed: Failed
disposed: "Disposed\nBỏ kết quả import đến muộn"
idle -> loading -> ready
loading -> failed: "Load / timeout / contract /\nmount failure"
loading -> disposed: Dispose
ready -> disposed: Dispose + unmount
failed -> ignored: "Import đến muộn"
ignored: "Bỏ qua, không mount"
```

Deadline giới hạn thời gian slot chờ import và validation; nó **không hủy native import**, không ngắt synchronous evaluation/mount và không cứu được module khóa main thread. Browser timer chỉ chạy khi event loop có cơ hội xử lý.

Mỗi slot có một generation. Dispose tăng generation để phần async cũ không mount vào instance đã hết vòng đời. Policy của lab là một attempt cho mỗi slot/document, không retry tại chỗ. Khi dùng router thật, tạo slot mới theo lifecycle route và bổ sung budget ở document scope nếu không muốn navigation reset giới hạn thử lại.

### Loader bỏ kết quả đến muộn

Tạo file mới dưới release shell `s18`. Không sửa bytes của s17 đã publish.

```js title="independent-deploy-lab/public/shell/s18/remote-slot.mjs" sourceFile="public/shell/s18/remote-slot.mjs" sourceRegion="main"
export function createSlot({ name, root, spec, revision, report, deadlineMs = 2000 }) {
  let generation = 0;
  let state = 'idle';
  let handle;

  function showFailure() {
    const message = document.createElement('p');
    message.setAttribute('role', 'alert');
    message.textContent = name === 'catalog'
      ? 'Catalog tạm thời không khả dụng. Giỏ hàng vẫn có thể dùng nếu đã sẵn sàng.'
      : 'Chưa lấy được thông tin giỏ hàng. Không thể xác nhận thao tác thêm hàng.';
    root.replaceChildren(message);
  }

  function emit(phase, kind, started, actualRelease = null) {
    report({
      shell: 's18', remote: name, config: revision,
      selectedRelease: spec.release, actualRelease,
      phase, kind, state,
      durationMs: Math.round(performance.now() - started),
    });
  }

  return {
    async start(props) {
      if (state !== 'idle') throw new Error('SLOT_ALREADY_STARTED');
      const mine = ++generation;
      const started = performance.now();
      let timer;
      let phase = 'load';
      let actualRelease = null;
      state = root.dataset.state = 'loading';
      const loading = document.createElement('p');
      loading.setAttribute('role', 'status');
      loading.textContent = `Đang tải ${name}…`;
      root.replaceChildren(loading);

      try {
        const remote = await Promise.race([
          import(spec.entry),
          new Promise((_, reject) => {
            timer = setTimeout(() => {
              const error = new Error('REMOTE_DEADLINE');
              error.code = 'DEADLINE';
              reject(error);
            }, deadlineMs);
          }),
        ]);
        clearTimeout(timer);
        if (mine !== generation) return null;

        phase = 'contract';
        if (remote.release !== spec.release || remote.contractVersion !== 1 ||
            typeof remote.mount !== 'function') {
          throw new Error('REMOTE_CONTRACT_INVALID');
        }
        actualRelease = remote.release;
        phase = 'mount';
        handle = remote.mount(root, props);
        if (typeof handle?.unmount !== 'function' ||
            (name === 'cart' && typeof handle.add !== 'function')) {
          throw new Error('REMOTE_HANDLE_INVALID');
        }
        state = root.dataset.state = 'ready';
        emit('ready', null, started, actualRelease);
        return handle;
      } catch (error) {
        if (mine !== generation) return null;
        // Với handle hợp lệ đã trả về, cleanup trước khi thay DOM.
        try { handle?.unmount?.(); } catch { /* Fallback vẫn phải hiện. */ }
        handle = undefined;
        state = root.dataset.state = 'failed';
        const kind = error.code === 'DEADLINE' ? 'timeout' :
          phase === 'contract' ? 'contract' :
          phase === 'mount' ? 'mount' : 'load-or-evaluate';
        root.dataset.kind = kind;
        showFailure();
        emit(phase, kind, started, actualRelease);
        return null;
      } finally {
        clearTimeout(timer);
      }
    },
    dispose() {
      if (state === 'disposed') return;
      ++generation;
      try { handle?.unmount?.(); } catch { /* Cleanup best-effort trong lab. */ }
      handle = undefined;
      state = root.dataset.state = 'disposed';
      root.replaceChildren();
    },
  };
}
```

<SourceRef project="thuc-hanh-remote-loi" file="public/shell/s18/remote-slot.mjs" region="main">Đối chiếu public/shell/s18/remote-slot.mjs</SourceRef>

`Promise.race` gắn rejection handler lên Promise import, kể cả khi timeout thắng trước. Khi import resolve muộn, đoạn code sau `await` không chạy lần hai, nên không mount muộn. Khi dispose trước khi import hoàn thành, generation check ngăn mount.

Tuy vậy, import vẫn có thể **evaluate top-level code** sau timeout. Remote phải không tự mount ở module scope; timers/listeners/subscriptions thuộc lifecycle mount/unmount. Metadata validation diễn ra sau evaluation, không phải sandbox hay security gate.

Nếu `mount()` throw sau khi tạo listener nhưng trước khi trả handle, shell không thể tự tìm hết tài nguyên đó. Provider phải cleanup khi mount thất bại một phần. Xóa DOM chỉ là fallback UI, không thay thế cleanup contract. Ví dụ throw trong test dưới đây cố ý không tạo tài nguyên trước khi throw.

### Pin config và khởi động hai slot độc lập

Validator giữ policy của bài trước: chỉ chọn URL same-origin theo release path đã biết, config fetch một lần cho mỗi document. Cart lỗi không ngăn catalog browse; catalog lỗi không ngăn cart mount.

```js title="independent-deploy-lab/public/shell/s18/main.mjs" sourceFile="public/shell/s18/main.mjs" sourceRegion="main"
import { createSlot } from './remote-slot.mjs';

const status = document.querySelector('#status');
const commandStatus = document.querySelector('#command-status');
let snapshot;
let cart;
const slots = [];

function parseConfig(raw) {
  if (raw?.schemaVersion !== 1 || typeof raw.revision !== 'string' ||
      !raw.revision.trim()) throw new Error('CONFIG_SCHEMA_INVALID');
  const remotes = {};
  for (const name of ['catalog', 'cart']) {
    const spec = raw.remotes?.[name];
    if (!spec || !/^r[1-9]\d*$/.test(spec.release) ||
        spec.contractVersion !== 1 || typeof spec.entry !== 'string') {
      throw new Error(`CONFIG_REMOTE_INVALID:${name}`);
    }
    const url = new URL(spec.entry, location.origin);
    if (url.origin !== location.origin ||
        url.pathname !== `/${name}/${spec.release}/entry.mjs` ||
        url.search || url.hash || url.username || url.password) {
      throw new Error(`CONFIG_URL_INVALID:${name}`);
    }
    remotes[name] = Object.freeze({ ...spec, entry: url.href });
  }
  return Object.freeze({ revision: raw.revision, remotes: Object.freeze(remotes) });
}

function report(event) {
  // Console thay cho telemetry transport; không log query/token hay payload cart.
  console.info('remote-state ' + JSON.stringify(event));
}

function onAdd(item) {
  if (!cart) {
    commandStatus.textContent = 'Chưa xác nhận thêm hàng: giỏ chưa sẵn sàng.';
    return;
  }
  try {
    cart.add(item);
    commandStatus.textContent = 'Đã thêm hàng vào giỏ.';
  } catch {
    commandStatus.textContent = 'Không thêm được hàng vào giỏ.';
  }
}

async function bootstrap() {
  const preview = new URL(location.href).searchParams.get('preview');
  if (preview !== null && !['r18', 'r19'].includes(preview)) {
    throw new Error('PREVIEW_INVALID');
  }
  const path = preview ? `/runtime/preview-${preview}.json` : '/runtime/config.json';
  const response = await fetch(path, {
    cache: 'no-store', signal: AbortSignal.timeout(5000),
  });
  if (!response.ok) throw new Error(`CONFIG_HTTP_${response.status}`);
  snapshot = parseConfig(await response.json());
  status.textContent = `s18 | config ${snapshot.revision} | ` +
    `selected catalog ${snapshot.remotes.catalog.release} | ` +
    `selected cart ${snapshot.remotes.cart.release}`;

  const makeSlot = (name) => {
    const slot = createSlot({
      name, root: document.querySelector(`#${name}`),
      spec: snapshot.remotes[name], revision: snapshot.revision, report,
    });
    slots.push(slot);
    return slot;
  };
  const cartSlot = makeSlot('cart');
  const catalogSlot = makeSlot('catalog');
  // Cùng khởi động; không await catalog rồi mới yêu cầu cart.
  const cartTask = cartSlot.start().then((handle) => { cart = handle; });
  const catalogTask = catalogSlot.start({ onAdd });
  await Promise.all([cartTask, catalogTask]);
}

bootstrap().catch(() => {
  status.textContent = 'Không đọc được cấu hình hợp lệ. Shop chưa sẵn sàng.';
  status.setAttribute('role', 'alert');
  for (const slot of slots) slot.dispose();
  cart = null;
  console.error('bootstrap-failed', { config: snapshot?.revision ?? null });
});
```

Trong dòng status, `selected` nghĩa là config đã chọn release đó, **không có nghĩa release đã chạy**. `remote-state` chỉ ghi `actualRelease` sau khi kiểm tra metadata thành công. Với module throw lúc evaluation, loader không biết release thực nên để `null`.

Lab giữ cart r7 theo bài trước. Callback thêm hàng ở đây là synchronous contract của cart fixture, không phải xác nhận backend và không có durable queue. Chưa có cart thì thao tác bị từ chối rõ ràng, không được tự replay khi cart tải xong.

`dispose()` phục vụ integration lifecycle và test riêng; HTML này không có route unmount. Không gọi nó trên mọi `pagehide` rồi kỳ vọng trang phục hồi từ back/forward cache vẫn usable. Khi thêm router, integration layer phải gắn dispose vào lifecycle thực của slot.

## Bước 3 chạy ma trận fault injection

### Browser test với context mới

Test dùng interception của Playwright, không sửa artifact đã publish. Mỗi ca có context riêng và chặn service worker. Routing của Playwright vô hiệu hóa HTTP cache cho các request bị routing trong context; context mới cũng tránh module cache của document cũ. Interception này không chứng minh CSP/CORS hoặc CDN policy production.

Tạo script dưới đây. Nó dùng preview r18 hoặc r19, nên **không sửa config stable** khi chạy fault matrix.

```js title="independent-deploy-lab/fault-tests.mjs" sourceFile="fault-tests.mjs" sourceRegion="main"
import assert from 'node:assert/strict';
import { chromium } from 'playwright';

const release = process.argv[2] ?? 'r19';
if (!['r18', 'r19'].includes(release)) throw new Error('RELEASE_INVALID');
const base = 'http://127.0.0.1:4173';
const entry = `${base}/catalog/${release}/entry.mjs`;
const browser = await chromium.launch();

async function textAt(page, selector, pattern) {
  await page.waitForFunction(({ selector, source }) => {
    return new RegExp(source).test(document.querySelector(selector)?.textContent ?? '');
  }, { selector, source: pattern.source });
}

async function stateAt(page, selector, state) {
  await page.waitForFunction(({ selector, state }) => {
    return document.querySelector(selector)?.dataset.state === state;
  }, { selector, state });
}

async function run(name, setup, check) {
  const context = await browser.newContext({ serviceWorkers: 'block' });
  const page = await context.newPage();
  const errors = [];
  const events = [];
```

### Promote release đang gặp lỗi

## Bước 5 giả lập shared version mismatch

Phần này chuyển sang **`shop-workspace`**, không chạy trong `independent-deploy-lab`. Native ESM không có webpack share scope nên contract major mismatch ở phần trước không thay thế test shared React.

### Tạo requirement không thể thỏa

Cần baseline của [Lab shell, catalog và cart](/docs/thuc-hanh/shop-shell-catalog-cart): shell ở `localhost:3000`, catalog ở `:3001`, cart ở `:3002`, async bootstrap và React shared strict singleton. Làm trên branch/worktree riêng, giữ bản config tốt để phục hồi.

Trong `apps/catalog/webpack.config.cjs`, chỉ thay entry `shared.react` của ModuleFederationPlugin đang có bằng:

```js title="shop-workspace/apps/catalog/webpack.config.cjs — chỉ entry shared.react"
react: {
  singleton: true,
  strictVersion: true,
  requiredVersion: '^99.0.0', // Fault fixture: cố ý không khớp React 19 của lab.
  import: false,            // Catalog không cung cấp local fallback React.
},
```

Không cài React 99 và không khai gian `version: '99.0.0'`. Đây là **requirement sai có chủ đích**, không phải một package release thật hay ví dụ migration hợp lệ. `import: false` giúp fault không vô tình được che bởi provider local của catalog. Shell/cart vẫn cung cấp React 19.

Giữ các entries `react-dom`, `react-dom/client`, JSX runtime `classic`, expose `./CatalogPage`, container names và `publicPath: 'auto'`. Không thêm plugin Federation thứ hai. Restart dev server catalog để nhận config mới; giữ shell và cart chạy:

```bash
npm run dev:catalog
```

### Quan sát fallback và phục hồi

Mở document shell mới ở `http://localhost:3000/cart` để shell render và cart controller khởi tạo trước. Sau đó chuyển sang catalog bằng link trong shell. Cần quan sát:

- Shell header và navigation còn hoạt động.
- Boundary catalog hiện “Màn hình chưa khả dụng”.
- Console có lỗi shared version chứa requirement `^99.0.0` và provider React 19, không chỉ một warning.
- Network entry/chunks catalog đã tải thành công; đây không phải entry 404 hay server chưa chạy.
- Chuyển lại cart trong cùng document vẫn usable; controller không được khởi tạo lại vì lỗi catalog.

Webpack có thể đăng ký remote providers trước thời điểm route import; không coi thứ tự click là bảo đảm thứ tự share-scope initialization. Fixture này dùng range không thể thỏa và không có provider local catalog, nên không phụ thuộc vào việc React 19 nào được chọn. Với lỗi thật giữa hai version hợp lệ, phải kiểm tra cả load order và version đã consume.

Dev overlay có thể che app khi lỗi runtime; đóng overlay để đọc fallback và kiểm chứng lại trên production build khi nghiệm thu. Stack trace và boundary UI phải cùng chỉ ra lỗi compatibility; chỉ thấy overlay không chứng minh failure đã được cô lập.

Khôi phục entry React của catalog về policy baseline:

```js title="Khôi phục shared.react của catalog"
react: {
  singleton: true,
  strictVersion: true,
  requiredVersion: dependencies.react,
},
```

Restart catalog rồi mở **document mới** của shell. Shell phải tải catalog, thêm hàng và mở cart được như baseline. Component/lazy type hoặc federation runtime trong tab đã lỗi có thể giữ kết quả cũ; reset boundary không đồng nghĩa reset mọi cache.

Đây là phục hồi config trong **development**, có rebuild remote và URL dev mutable. Không gọi nó là rollback production. Rollback production phải chọn artifact tốt đã kiểm chứng theo cơ chế selection của hệ thống, giữ bytes bất biến và kiểm chứng tab cũ/document mới như bước 4. Nếu fixed remote URL của shop chưa hỗ trợ selection, bạn chưa có cơ chế rollback độc lập chỉ bằng đổi runtime config.

<Callout type="warn" title="Đừng làm version check im lặng">
  Không chữa bằng `strictVersion: false`, bỏ singleton, thêm `eager: true` hoặc sửa metadata provider cho “đúng” version mong muốn. Các cách đó có thể che lỗi mà vẫn đưa component vào renderer không tương thích. Lỗi compatibility cần release set hợp lệ; lỗi network cần sửa đường tải. Hai loại không dùng cùng một cách phục hồi.
</Callout>

## Những bẫy dễ làm test xanh giả

**Dừng server sau khi code đã tải.** Module/controller đang trong memory vẫn hoạt động. Muốn test download failure, chặn request trước khi document mới tải entry hoặc trước lazy import chưa xảy ra.

**Bật offline toàn trang để test catalog.** Shell/config/cart cũng có thể lỗi, nên không chứng minh isolation của catalog. Bắt đầu bằng một URL entry cụ thể; thêm global offline như một scenario khác nếu cần.

**Đổi key nhưng dùng cùng lazy type đã reject.** React cache Promise cho lazy type; boundary reset không bắt lazy gọi loader lại. Tạo attempt type mới mới có loader invocation mới, nhưng federation/module cache vẫn là một lớp khác. Không thêm nút “Thử lại” trước khi có policy cache và budget đã test.

**Coi timeout là cancellation.** Slot chỉ ngừng chờ và không mount muộn; module vẫn có thể evaluate. Không mở attempt song song tùy tiện hoặc đổi release ngay trong window đã có singleton/share scope đang chạy.

**Dùng query timestamp để ép tải code.** URL mới có thể tạo module identity mới, lặp top-level side effects và không xử lý root cause. Dùng release path bất biến cùng snapshot config, không `?t=Date.now()` như recovery mặc định.

**Assert chỉ có text fallback.** Bạn còn phải assert slot cart, số lượng hàng, phase telemetry, không mount muộn và không report trùng. Vùng cart hiện `0` vì chưa tải được không phải graceful degradation.

**Thấy test fault matrix pass rồi coi release an toàn mọi mặt.** Matrix này không bao phủ backend outcome mơ hồ, cross-origin policies, main-thread lockup, React root isolation, CSS, memory leaks lâu dài hay full accessibility. Bổ sung tests theo boundary thật trước production.

Bài tập tiếp theo: viết một incident note từ evidence vừa thu được, gồm release set bị ảnh hưởng, phase lỗi, capability vẫn dùng được, selection rollback và cách xử lý tab cũ. Nếu note phải dùng câu “có lẽ cache” mà không chỉ ra URL, response hoặc document lifecycle, hãy chạy lại đúng ca đó để bổ sung bằng chứng.

## Tài liệu tham khảo và đọc tiếp

- [MDN — Dynamic import](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import): loading/evaluation failures và module cache.
- [Webpack — ModuleFederationPlugin](https://webpack.js.org/plugins/module-federation-plugin/): `requiredVersion`, `strictVersion`, `singleton` và local fallback.
- [Playwright — Network](https://playwright.dev/docs/network): interception, abort và mock responses.
- [Playwright — Page routing](https://playwright.dev/docs/api/class-page#page-route): routing và HTTP cache/service worker caveats.
- [React — lazy](https://react.dev/reference/react/lazy): Promise caching theo lazy type.
- [React — Error Boundaries](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary): phạm vi bắt lỗi render.
